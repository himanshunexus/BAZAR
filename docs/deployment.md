# BAZAR - Deployment Guide

## Local Development

```bash
# 1. Clone and setup
cd "BAZAR HUB"
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# 2. Install WeasyPrint system dependencies (required for PDF generation)
# macOS:
brew install pango cairo gdk-pixbuf libffi
# Ubuntu/Debian:
# sudo apt-get install libpango-1.0-0 libcairo2 libgdk-pixbuf-2.0-0 libffi-dev

# 3. Run migrations
python manage.py migrate

# 4. Create superuser
python manage.py createsuperuser

# 5. Run development server
python manage.py runserver
```

Visit http://127.0.0.1:8000

## Seeding Data

The `seed_data` management command creates the default shop and product categories. `start.sh` runs this command on each server start, and it uses `get_or_create`, so repeated runs do not duplicate categories. It does not create sample seller accounts, shops, or products.

For local development, run:

```bash
python manage.py seed_data
```

Create seller accounts, shops, and products through the app or Django admin.

## Deployment on Render

1. Push code to GitHub
2. Create a **New Web Service** on Render
3. Connect your repository
4. Render auto-detects `render.yaml` and configures the free web service
5. Add/update environment variables on Render dashboard:
   - `SECRET_KEY` = (auto-generated by render.yaml)
   - `ALLOWED_HOSTS` = `.onrender.com`
   - `CSRF_TRUSTED_ORIGINS` = `https://your-app.onrender.com` (your actual Render URL)
   - `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, and `CLOUDINARY_API_SECRET` = rotated Cloudinary credentials

The Render free web service uses SQLite on ephemeral storage. Categories are seeded when the service starts, but user-created data can disappear when the service restarts, spins down, or redeploys. Use this only for a demo.

**Important notes:**
- `CSRF_TRUSTED_ORIGINS` must be the exact full URL (no wildcards)
- `SECURE_SSL_REDIRECT` is set to `False` because Render terminates SSL at the proxy
- WeasyPrint requires system libraries — use Render's Docker runtime if PDF generation is needed

## Environment Variables Reference

| Variable | Description | Required |
|----------|-------------|----------|
| `SECRET_KEY` | Django secret key | Yes |
| `DJANGO_SETTINGS_MODULE` | Settings module path | Yes (production) |
| `ALLOWED_HOSTS` | Comma-separated hostnames | Yes (production) |
| `CSRF_TRUSTED_ORIGINS` | Comma-separated full URLs (e.g. `https://app.onrender.com`) | Yes (production) |
| `CLOUDINARY_CLOUD_NAME` | Cloudinary cloud name | Required for remote image uploads |
| `CLOUDINARY_API_KEY` | Cloudinary API key | Required for remote image uploads |
| `CLOUDINARY_API_SECRET` | Cloudinary API secret | Required for remote image uploads |

## Static & Media Files

- **Static files**: Served by WhiteNoise (included in middleware)
- **Media files**: Product and shop uploads use Cloudinary when the three Cloudinary environment variables are configured.

## WeasyPrint System Dependencies

WeasyPrint (used for PDF catalog generation) requires system-level C libraries:
- **Pango**, **Cairo**, **GDK-PixBuf**, **libffi**

On Render's native Python runtime, these are NOT pre-installed. Options:
1. Switch to Render's Docker runtime and install them in a Dockerfile
2. Disable the PDF feature in production until a Docker setup is ready
